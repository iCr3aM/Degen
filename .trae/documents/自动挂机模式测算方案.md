# 自动挂机模式（天眼）—— 先离线出数，再决定是否做成开关

## Context

你想知道「末期挂机会有多少钱」，并提出在游戏里加一个隐藏开关，开启后自动在**每月最高点做空、最低点做多**。

这个需求最终要回答的其实是一个**数字**，而不是一个功能。所以本方案分两段：

- **第一段（立即执行）**：写一个临时离线脚本，用**与游戏完全同源的引擎代码**跑完 105,192 根真实小时 K 线，几秒内给出末期权益、反转次数、是否爆仓、是否被供应量上限卡死。跑完即删，**零代码污染、零 UI 风险**。
- **第二段（拿到数字后再定）**：如果这个数字值得你在游戏里亲眼看着它涨，再按同一套口径落地隐藏开关。**第一段的数字不好看，第二段就不做。**

已确认的三项口径（你刚才选定）：
1. 杠杆 = **天眼最优**（每次开仓前反推一个刚好不会被强平的杠杆）
2. 隐藏入口 = **连点顶栏「Degen」标题 5 次**（第二段才用）
3. 数字显示 = **自动模式下切紧凑格式**（第二段才用）

## 已确认的承重事实（决定了脚本必须怎么跑）

### ① 未来数据可读，无技术障碍
[market.js](file:///f:/Cr3aM/Desktop/Degen/src/core/market.js#L109-L120) 的 `candleAt(sym, i)` 读的是内存里整条序列，**任意索引都能取**，包括 `s.i` 之后的未来根。「禁止提前看未来」只是 UI 层 `view.js` 的 `clampRight`。找月度极值不需要任何新数据、不需要改数据包。

### ② 引擎结构把玩法逼成「反转」而不是「两单独立」
[engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L186-L188) 的 `openTrade` 开头：

```js
if (posOf(s, s.sym)) return { ok: false, why: `${s.sym} 已有持仓，先平仓` };
```

**一个币只许一条仓位。** 所以「最低点做多 + 最高点做空」不可能各挂一单，只能退化为：

> 每到月内极值就把当前仓位平掉，再按新方向开一单 —— 低点持多、高点持空。

这同时消掉了一个歧义：同一个月里高低点谁先到，不用区分，按 `s.i` 排序后依次反转即可。

### ③ 成交价是**那根 K 线的收盘价**，不是极值价
[engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L42-L44)：

```js
export function markPrice(s, sym = s.sym) { return closeAt(sym, s.i); }
```

所以「在月最低点做多」实际是**在那根的收盘价**买入，而那不是最低价。这是口径损耗，脚本里必须如实反映，不能假装买在最低点。

### ④ 「天眼最优杠杆」的反推公式
由 [positions.js](file:///f:/Cr3aM/Desktop/Degen/src/core/positions.js) 的清算缓冲 `1/lev − maintRate`（`GAME.maintRate = 0.005`）推出，在持有多单、入场价 `F`、持有区间内最不利价为 `W` 时：

- 多单安全条件 `low > F × (1 − (1/lev − maint))` ⟹ **`lev < 1 / (1 − W/F + maint)`**
- 空单安全条件 `high < F × (1 + (1/lev − maint))` ⟹ **`lev < 1 / (W/F − 1 + maint)`**

`openTrade` 里 `lev = Math.max(1, Math.min(s.lev, maxLeverageAt(timeOf(s), s.ex)))`，所以叠上交易所档位上限后写回 `s.lev` 即可，超出部分会被自动夹住。

⚠️ **必须留安全垫**，因为三件事会啃掉缓冲：
- **资金费**每 8 游戏小时从 `pos.margin` 里扣（[settleFunding](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L601-L641)），`pos.margin` 变小 ⇒ 强平价贴近。持有几周、费率上限 0.5%/期，这一项**很凶**。
- **开平两次手续费**（`feeRateOf(pos.ex)`）
- **平仓滑点**（`impactFor`，按 `liqOf` 平方根冲击）

⇒ 实现上按 `W` 再外扩一档（保守取更极端的 `W'`）＋ 末尾乘一个安全系数，**并把实际发生的爆仓如实报出来**，而不是假设它不会爆。

### ⑤ 供应量上限**会**卡住天眼 —— 而且很早就卡
[config.js](file:///f:/Cr3aM/Desktop/Degen/src/core/config.js#L242-L248)：`SUPPLY_CAP.BTC = 3e6`（300 万枚）。

[state.js](file:///f:/Cr3aM/Desktop/Degen/src/core/state.js#L121-L125) 的 `capturedOf` **只看当前持仓**：

```js
export function capturedOf(s, sym) {
  const pos = s.positions[sym];
  if (!pos || pos.side !== 'long' || pos.otc) return 0;
  return pos.size;
}
```

⟹ 上限约束的其实是**单笔多头的名义规模**，不是累计消耗。按真实 BTC 价换算门槛：

| 时刻 | BTC 约价 | 单笔多头名义上限 |
| --- | --- | --- |
| 2013 | ~$13 | 约 **$3,900 万** |
| 2017-12 | ~$19,000 | 约 **$570 亿** |
| 2021 | ~$50,000 | 约 **$1,500 亿** |

开局 $3,000、天眼杠杆十几倍 ⇒ **2013 年内就可能撞上**。撞上之后 `openTrade` 会返回 `已触及供应量上限，无法继续买入`，做多直接失效 —— 策略从那一刻起就残废了。

**这正是 `ROADMAP §十一` 的结论**：「单笔名义上限是唯一能封顶的那一条」。所以脚本必须**明确报告第一次被拒的时刻与当时权益**，那是真正的「天花板落点」。

### ⑥ 归零不等于结束，而是进「待借贷」
[engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L321-L331) 的 `checkRuin`：

```js
if (!s.loaned) { s.pending = 'loan'; s.paused = true; ... return false; }
```

置上 `s.pending` 之后，`advanceOneHour` 开头 `if (s.over || s.pending) return;` 会**永久早退** ⇒ 循环会空转到天荒地老。

⇒ 脚本的循环退出条件必须是 `s.over || s.pending`，**两个都要判**。天眼模式**不借钱**（借了会污染数字），所以撞上 `pending` 就等于「本局在此时刻归零」，如实报告即可。

## 第一段：离线测算脚本（立即执行）

### 新建临时文件 `tools/_auto.mjs`

按项目已有约定：**临时脚本、跑完即删**（同 `tools/_life.mjs` 的处理）。

**1）数据装载 —— 走既有离线桩套路**
不重新发明。沿用离线断言脚本那套：`zlib.gunzipSync` 读 `public/data/*.bin` ＋ `raw.buffer.slice(raw.byteOffset, raw.byteOffset + raw.byteLength)` 保证 4 字节对齐，给 `market.js` 挂一个 `globalThis.fetch` 桩（把 `public/data/` 下的文件按路径喂回去），再正常 `import` 引擎。**这样引擎代码一行不改、口径与游戏逐位相同。**

**2）月度极值表 —— 只算一次，纯函数**

```js
// 对每个 UTC 自然月，找月内 high 最大、low 最小的那根（并列取最早出现的）
// 只用 hasCandle(sym, i) 为真的根，跳过该币还没上线的月份
// 若某月最值与次值落在同一根（高即低），该月不产生事件
```

产出 `events: [{ i, kind: 'low' | 'high' }]`，按 `i` 升序。

**3）主循环 —— 直接驱动真引擎**

```js
for (let i = 0; i < GAME.candles; i++) {
  // 到极值点：先平（若有仓）、再按 kind 反推天眼杠杆并开仓
  // 其余小时：只是 advanceOneHour(s)
  advanceOneHour(s);
  if (s.over || s.pending) break;      // ⑥ 两个都要判
}
```

- 开仓方向：`kind === 'low'` → `openTrade(s, 'long', 1)`；`kind === 'high'` → `openTrade(s, 'short', 1)`
- 杠杆：按 ④ 的公式反推，写进 `s.lev` 后交给 `openTrade`（超出交易所档位会被 `maxLeverageAt` 自动夹住）
- `s.chan` 保持 `'book'`（OTC 只有现货 1x，会把天眼杠杆废掉）；`s.ex` 保持不动（不换所，避开 Mt.Gox 归零那套）
- 记录每次被 `openTrade` 拒绝的原因（尤其供应量上限 ⑤）

**4）输出（这是本段真正的交付物）**

| 项 | 说明 |
| --- | --- |
| 末期权益 | 原始量级 ＋ 紧凑写法（如 `$8.15e+100`） |
| 反转次数 | 实际成功开仓的次数（对照月度极值总数，看被拒了多少） |
| 结局 | 活到 2024-12-31 / 爆仓归零（给出时刻）/ 被供应量上限卡死（给出时刻） |
| 首次被拒 | ⑤ 的落点：第一次 `已触及供应量上限` 的时刻、当时权益、当时杠杆 |
| 年末权益 | 2013–2024 每年 12-31 的权益，看复利形状 |
| 对照三行 | 同样策略换成 **1x 现货** / **3x** / **玩家当前档（如 100x）** ⇒ 证明「天眼最优」到底比它们强多少 |

### 本段不做的事（守规矩）

- **不动 `src/` 下任何一个文件**
- **不动 `ROADMAP.MD` / `HANDOFF.MD`**（等数字出来、你拍板后再决定要不要记一笔）
- **不 commit**（临时脚本跑完删除，工作树保持干净）
