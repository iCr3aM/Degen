## 2. 地基：USD 与 USDT 分离

### 2.1 为什么必须先做这个

现在是**单一 `books[ex]`**（一个数）。①②⑤（用户点名的资产页三项）＋ 三条已拍板规则
（优先扣 USDT / 不足补 USD / 合约必须 USDT）**全都落不下来**：一个数没法同时表示两种钱。

### 2.2 目标结构

```
s.books[ex] = { usd: 0, usdt: 0 }        // 每个交易所两格（原来只有一格数）
s.transfer  = { …, cur: 'usd'|'usdt' }   // 在途的钱是哪种
```

- **取钱优先级**：`spendOf(s, amount, mustUsdt)` —— 合约（`!isSpot`）**只认 USDT**；
  现货先扣 USDT、不够的部分再扣 USD（已拍板）。
- **`cashOf(s)` 语义升级**：返回该所「可用于开仓的总额」= `usd + usdt`（仅用于展示与旧断言，
  真实扣款走 `spendOf`）。

### 2.3 年代规则（与已落地的四段 rail 对齐）

| 年代 | 交易所里装的是什么 | 跨所搬的是什么 |
|---|---|---|
| 2013-01 ～ 2014-11-19 | **USD**（Mt.Gox / Bitfinex 当年就是美元账户） | USD（`wire` 电汇，$20） |
| 2014-11-20 起 | 两种都可能有 | **USDT**（`omni` / `erc20` / `trc20`） |

- **开局**：`books.mtgox.usd = 3000`，`usdt = 0` ⇒ 玩家**第一天就在 Mt.Gox 用美元交易**，
  与改动前的开局观感**逐位相同**（这是硬要求：2013 年本来就没有 USDT，不该逼玩家先换钱）。
- **2014-11-20 起**：链上通道只搬 USDT ⇒ 想搬钱就必须先「买 U」—— **这正是用户要的那一步**。
- HUD / 资产页按年代显示单位：2014-11-20 前那格是 `$`，之后是 `₮`（同一格数据的两种读法，
  与「Bitfinex 的美元余额长期就是 USDT」这一史实一致）。

### 2.4 受影响的清单（实施时逐条改）

`state.js`（结构 ＋ `STATE_VERSION` 13）、`engine.cashOf/equity/openTrade/closeTrade/liquidateAll/
switchExchange/advanceOneHour(到账)`、`render.js`（HUD 两格、资产页、选所弹层余额文案）、
`main.js`（`$100 万门槛`判断、加仓分派）、`god.js`（填入资金）、`save.js`（无迁移，版本不符即弃档）。

三条建模规矩：

1. **危机写成「尖峰」而不是「缓坡」**：锚点成对出现（前一天 1.000 / 当天冲击值 / 次日 0.98 或 1.000），
   线性插值后自然形成**日内 V 形**。史实口径正是「官方与美联储资料显示事件当天即回锚」，
   而两个危机（2018-10-15 / 2022-11-09）都**按单日冲击建模**。
2. **不加 σ 放大**（与「价格上不叠加人工涨跌幅」那条红线同源）：恐慌已经写在锚点里，
   再乘一次 σ 就是对同一事件**双重计价**。
3. **双向**（可折价可溢价），与 OTC 溢价「恒定对玩家不利」**刻意不同** ——
   用户要的是「**真实**」：2017-04 与 2018-10 那两年，买 U 就是**捡便宜**。

⚠️ **不采用的数字**（检索时逐条排除）：
- 2015-02 的 $0.57 —— 早期无深度、报价失真，不作锚点；
- 中文媒体的「溢价 14.29%（2020-03）」—— 那是**场外人民币 OTC 报价**口径，不是美元计价；
- CoinCodex 记的 2018-07 $1.51 / CoinLore 记的 2018-12 $1.29 —— **未能证实**为真实可成交价。

## 4. 资金曲线

- **采样**：每游戏日收盘记一个权益值 → `s.eq = [e0, e1, …]`（隐含「第 n 天」为横轴）。
  全程 4,383 个点 ≈ 45 KB，存档可接受（localStorage 上限 5 MB）。
  ⚠️ 上帝模式「跳日期」是**逐小时重放**（既有实现）⇒ 天然会经过每一天，不会漏采样。
- **画法**：资产页顶部一张 `canvas`（高 ≈ 110px），**对数纵轴**（$3,000 → $10M 的跨度用线性会把
  前半段压成一条线），起点画一条 `$3,000` 基准虚线。
- **增量**：天序号一变就 push 一个点并重绘，不做全量重算。

## 5. 同币加仓（修「1/4 · 1/2 真实可下性」）

用户原话：「100 美元选 1/4 做多，逐仓是否应该可以选择把剩下的钱放入保证金内？或者假设不放入，
那么他还有 3/4 的美元，这时候应该还可以继续加仓。」

### 5.1 方案：**合并进同一条仓位**（不新增仓位槽）

保持「每个币最多一条仓位」这条不变量（它撑着 `posOf` / 持仓条 / 图表强平线 / 存档全部代码），
加仓 = 把那笔新单**并进**已有仓位：

| 字段 | 合并式 |
|---|---|
| `size` | `+ addSize` |
| `notional` | `+ margin × lev` |
| `margin` | `+ addMargin` |
| `openFee` | `+ margin × lev × feeRate`（各收各的，不重算） |
| `entry` | **按 `size` 加权平均** —— `(entry×size + fill×addSize) / (size + addSize)` |

### 5.2 允许与拒绝

- **允许**：同币 ＋ 同方向 ＋ **同杠杆** ＋ 同性质（现货/合约一致）＋ 同通道（同为 OTC 或同为盘口）。
- **拒绝**：反方向（要反手就**先平仓**，不默认为玩家反手）、杠杆不同、性质不同、通道不同 ——
  各给一句明确文案，不静默失败。
- **「把剩下的钱也放进保证金」怎么回答**：逐仓下**不需要**这一步 —— 钱留在账上就是你的可用保证金，
  再点一次 1/4 就加进去了（比「一次性锁定全部本金」更灵活，也避免玩家误操作把全部身家压上）。

## 7. 手机端 UI 打磨方案（**精细版** · 二轮调研 2026-09-30）

> 调研来源（二轮，两组并行检索）：Apple HIG / Material 3（Motion tokens、Dark theme）/
> WCAG 2.1 & 2.2 / MDN Canvas 优化 / 币安·OKX·Robinhood 手机端 / 挂机类（idle）游戏 UI 通行做法。
> 结论已与 `style.css` **逐条对照**。凡与「硬约束 ①–⑤」冲突的建议**一律不采纳**，冲突逐条列在 §7.0。
> 目标视口 **390×844**（兼容 360px 窄屏）；基座：`font-size: 13px`、全直角、
> 纵向间距只有 8 / 12 两档、`.num` 已全局 `tabular-nums`。

### 7.0 先处理冲突：调研建议 vs 本项目硬约束

| # | 调研建议 | 本项目现状 | 结论 |
|---|---|---|---|
| 1 | 底部 Tab 52–56px（Material 56dp / iOS 49pt＋安全区） | 44px（为 K 线让高度，K 线是全屏唯一弹性块） | **不采纳** —— 44 已达 44pt 命中底线，抬到 52 要白吃 8px 行情 |
| 2 | 深色底 `#121212` / 面板 `#1E1E1E` | `#0d0f12` / `#151a20`（四层灰阶、不带蓝相） | **不换色** —— 只做对比度验算（§7.3） |
| 3 | 分隔线用 `.5px`（DPR≥2） | 全站 `1px` | **限范围采纳** —— 只在 `.tabs` 上边试点（§7.8） |
| 4 | Canvas DPR 封顶 2（省性能） | `Math.min(3, dpr)` | **不采纳** —— 已有 80ms 节流，降 DPR 的收益小于清晰度损失 |
| 5 | 主数值 32–48px | 最大 20px（`.over b`） | **局部采纳** —— 只把资产页「总资产」提到 18px（全屏唯一主数值） |
| 6 | 空状态＝图标＋标题＋1 个 CTA | 一行中性占位 | **只采纳「一行、不道歉」** —— 不引入图标与 CTA |
| 7 | 「不可用」置灰而非隐藏 | 已二分：`.opt.off` 虚线置灰（有但不可用）/ `hidden`（时代未到） | **保持** —— 并把它写成显式规则（§7.9） |
| 8 | 长按激活十字光标 | 无 | **不做** —— K 线不做十字光标（§7.10） |
| 9 | 间距走 8pt grid（8 / 12 / 16 / 24） | 只有 8 与 12 两档 | **保持两档** —— 硬约束 ④ |

### 7.1 审计纠错：上一版 §7.1 的两处**事实错误**（先纠正，再谈打磨）

1. ~~「单界面 **5 档**字重（400/500/600/700）」~~ → **错**。全文件 `font-weight` 只出现 **12 次、全是 600**，没有 500/700。
   但**实际渲染仍是三档** —— 因为 `<b>` 未显式指定时吃浏览器默认（700）：
   - **600**：`.top .who b` / `.hud .cell b` / `.chart-head b` / `.as-head b` / `.menu-box h3` …
   - **700（隐式）**：`.posbar b`（[style.css:382](file:///f:/Cr3aM/Desktop/Degen/src/ui/style.css#L382)）、`.prow > b`、`.over b` …

   ⇒ **同一个 `<b>` 在 HUD 是 600、在持仓条是 700**，这是全站唯一的字重不一致。
   修法是**一条兜底**（`b, strong { font-weight: 600 }`），不是「收敛 5 档到 3 档」——见 §7.12 ①。

### 7.4 触摸命中区（逐项实测；**不改视觉高度**）

| 控件 | 现状（高 × 宽） | 判定 | 落点 |
|---|---|---|---|
| `.tab`（底部三页） | 44 × ~122 | ✅ 达标 | 不动 |
| `.act`（做多 / 做空 / 平仓） | 40 × ≥170 | 差 4pt，但宽度是次级键两倍 | **不动**（加高会动固定块高度预算 ⇒ 挤 K 线） |
| `.opt`（金额档 / 杠杆档） | 32 × 55–97 | 短边不足 | **伪元素扩到 40** |
| `.sym`（币种） | 32 × ~68 | 短边不足 | 同上 |
| `.ic`（暂停 / 重开 / 交易所） | 32 × 42+ | 短边不足 | 同上 |
| `.pick-row`（换所弹层） | 32 × 全宽 | 短边不足 | 同上（按实测留白复核） |

实现（**不动 `height`**，所以一毫米高度预算都不占）：

```css
.opt, .sym, .ic, .pick-row { position: relative; }
.opt::after, .sym::after, .ic::after, .pick-row::after {
  content: ''; position: absolute; inset: -4px 0;
}
```

> 为什么正好 4px：纵向留白只有 8（硬约束 ④），上下各伸 4 **恰好相接、不重叠**；
> 扩完短边 40px，落在 WCAG 2.2 AA 的 24px 之上、逼近 Apple 的 44pt，而**观感零变化**。

### 7.5 动效层（本项目**最大的缺口**：全文件 `transition` 命中 **0** 次）

| # | 落点 | 属性 | 时长 |
|---|---|---|---|
| 1 | `.tab` / `.sym` / `.opt` / `.ic` 的选中态 | color / border-color / background | `--dur-fast` |
| 2 | `.act:active` | 在现有 `brightness(.88)` 上补 `transform: scale(.985)` | `--dur-fast` |
| 3 | `.page.on` 切页 | **只 `opacity` 淡入**（不位移） | `.12s` |
| 4 | `.pick-back` / `#overlay` / `.confirm` / `.over` / `.menu-back` | `opacity` | `--dur` |
| 5 | 资产页「总资产」换值 | 背景闪一下（`animation` 一次性） | `.15s` |

三条纪律：
- **只动 `opacity` / `transform`**，不动 `width / height / top`（后者每帧触发布局，50x 下会掉帧）；
- **只在 `.on` 类切换处挂 transition** —— `update()` 里按签名重建的节点（速度档、杠杆档、
  持仓列表、K 线左上角）**插入那一帧就会播一次动画**，观感是「界面一直在闪」；
- `@media (prefers-reduced-motion: reduce)` 下把全部 transition / animation 压到 `0.01ms`（WCAG 2.3.3）。

> ❌ 不做「数字滚动」（挂机游戏那套 1s 滚动）：本项目数值在高倍速下每帧都在变，滚动会堆积卡顿。
