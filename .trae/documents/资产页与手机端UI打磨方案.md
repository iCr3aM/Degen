## 2. 地基：USD 与 USDT 分离

### 2.1 为什么必须先做这个

现在是**单一 `books[ex]`**（一个数）。①②⑤（用户点名的资产页三项）＋ 三条已拍板规则
（优先扣 USDT / 不足补 USD / 合约必须 USDT）**全都落不下来**：一个数没法同时表示两种钱。

### 2.2 目标结构

```
s.books[ex] = { usd: 0, usdt: 0 }        // 每个交易所两格（原来只有一格数）
s.transfer  = { …, cur: 'usd'|'usdt' }   // 在途的钱是哪种
```

- **取钱优先级**：`spendOf(s, amount, mustUsdt)` —— 合约（`!isSpot`）**只认 USDT**；
  现货先扣 USDT、不够的部分再扣 USD（已拍板）。
- **`cashOf(s)` 语义升级**：返回该所「可用于开仓的总额」= `usd + usdt`（仅用于展示与旧断言，
  真实扣款走 `spendOf`）。

### 2.3 年代规则（与已落地的四段 rail 对齐）

| 年代 | 交易所里装的是什么 | 跨所搬的是什么 |
|---|---|---|
| 2013-01 ～ 2014-11-19 | **USD**（Mt.Gox / Bitfinex 当年就是美元账户） | USD（`wire` 电汇，$20） |
| 2014-11-20 起 | 两种都可能有 | **USDT**（`omni` / `erc20` / `trc20`） |

- **开局**：`books.mtgox.usd = 3000`，`usdt = 0` ⇒ 玩家**第一天就在 Mt.Gox 用美元交易**，
  与改动前的开局观感**逐位相同**（这是硬要求：2013 年本来就没有 USDT，不该逼玩家先换钱）。
- **2014-11-20 起**：链上通道只搬 USDT ⇒ 想搬钱就必须先「买 U」—— **这正是用户要的那一步**。
- HUD / 资产页按年代显示单位：2014-11-20 前那格是 `$`，之后是 `₮`（同一格数据的两种读法，
  与「Bitfinex 的美元余额长期就是 USDT」这一史实一致）。

### 2.4 受影响的清单（实施时逐条改）

`state.js`（结构 ＋ `STATE_VERSION` 13）、`engine.cashOf/equity/openTrade/closeTrade/liquidateAll/
switchExchange/advanceOneHour(到账)`、`render.js`（HUD 两格、资产页、选所弹层余额文案）、
`main.js`（`$100 万门槛`判断、加仓分派）、`god.js`（填入资金）、`save.js`（无迁移，版本不符即弃档）。

### 3.1 交互（LESS IS MORE）

资产页新增一张卡片：**当前价 `1 USDT = $1.002`** ＋ 金额档（沿用操作区那套 1/4 · 1/2 · 全部）
＋ 一枚「买入」键。买完立刻到账（USDT 在**同一家所内**兑换，不过链、不产生矿工费）。

- 只在 **2014-11-20 之后**出现（`usdtLiveAt`）；之前那一格按 §2.3 直接就是 USD，不需要换。
- 反向「卖 U」**不做**（LESS IS MORE；跨所搬 U 已经给了出口）。

三条建模规矩：

1. **危机写成「尖峰」而不是「缓坡」**：锚点成对出现（前一天 1.000 / 当天冲击值 / 次日 0.98 或 1.000），
   线性插值后自然形成**日内 V 形**。史实口径正是「官方与美联储资料显示事件当天即回锚」，
   而两个危机（2018-10-15 / 2022-11-09）都**按单日冲击建模**。
2. **不加 σ 放大**（与「价格上不叠加人工涨跌幅」那条红线同源）：恐慌已经写在锚点里，
   再乘一次 σ 就是对同一事件**双重计价**。
3. **双向**（可折价可溢价），与 OTC 溢价「恒定对玩家不利」**刻意不同** ——
   用户要的是「**真实**」：2017-04 与 2018-10 那两年，买 U 就是**捡便宜**。

⚠️ **不采用的数字**（检索时逐条排除）：
- 2015-02 的 $0.57 —— 早期无深度、报价失真，不作锚点；
- 中文媒体的「溢价 14.29%（2020-03）」—— 那是**场外人民币 OTC 报价**口径，不是美元计价；
- CoinCodex 记的 2018-07 $1.51 / CoinLore 记的 2018-12 $1.29 —— **未能证实**为真实可成交价。

## 4. 资金曲线

- **采样**：每游戏日收盘记一个权益值 → `s.eq = [e0, e1, …]`（隐含「第 n 天」为横轴）。
  全程 4,383 个点 ≈ 45 KB，存档可接受（localStorage 上限 5 MB）。
  ⚠️ 上帝模式「跳日期」是**逐小时重放**（既有实现）⇒ 天然会经过每一天，不会漏采样。
- **画法**：资产页顶部一张 `canvas`（高 ≈ 110px），**对数纵轴**（$3,000 → $10M 的跨度用线性会把
  前半段压成一条线），起点画一条 `$3,000` 基准虚线。
- **增量**：天序号一变就 push 一个点并重绘，不做全量重算。

## 5. 同币加仓（修「1/4 · 1/2 真实可下性」）

用户原话：「100 美元选 1/4 做多，逐仓是否应该可以选择把剩下的钱放入保证金内？或者假设不放入，
那么他还有 3/4 的美元，这时候应该还可以继续加仓。」

### 5.1 方案：**合并进同一条仓位**（不新增仓位槽）

保持「每个币最多一条仓位」这条不变量（它撑着 `posOf` / 持仓条 / 图表强平线 / 存档全部代码），
加仓 = 把那笔新单**并进**已有仓位：

| 字段 | 合并式 |
|---|---|
| `size` | `+ addSize` |
| `notional` | `+ margin × lev` |
| `margin` | `+ addMargin` |
| `openFee` | `+ margin × lev × feeRate`（各收各的，不重算） |
| `entry` | **按 `size` 加权平均** —— `(entry×size + fill×addSize) / (size + addSize)` |

### 5.2 允许与拒绝

- **允许**：同币 ＋ 同方向 ＋ **同杠杆** ＋ 同性质（现货/合约一致）＋ 同通道（同为 OTC 或同为盘口）。
- **拒绝**：反方向（要反手就**先平仓**，不默认为玩家反手）、杠杆不同、性质不同、通道不同 ——
  各给一句明确文案，不静默失败。
- **「把剩下的钱也放进保证金」怎么回答**：逐仓下**不需要**这一步 —— 钱留在账上就是你的可用保证金，
  再点一次 1/4 就加进去了（比「一次性锁定全部本金」更灵活，也避免玩家误操作把全部身家压上）。

## 7. 手机端 UI 打磨方案

> 依据：本轮网络调研（Apple HIG / Material 3 / WCAG 2.1 / MDN / 1px.com +
> 币安等交易 App 与挂机类游戏 UI 的通行做法），下文每条都落到**本项目的具体文件与数值**。
> 目标视口 **390×844**（兼容 360px 窄屏），当前基座：`font-size: 13px`、全直角、
> 纵向间距只有 8 / 12 两档、`tabular-nums` 已全局启用。

### 7.1 排版与数字（多数已达标，补三处）

| 项 | 现状 | 本轮落点 |
|---|---|---|
| 正文字号 | 13px（≥12px 下限 ✅） | 不动 |
| 等宽数字 | `.num` 有 `tabular-nums` ✅ | 补 `font-feature-settings:"tnum" 1` 兜底（`--mono` 回退到系统字体时 tnum 可能失效） |
| 字重层级 | 单界面 **5 档**（400/500/600/700 + `.gold` 变体） | 收敛到 **3 档**：正文 400 / 标签与按钮 500 / 数字与标题 600 |
| 字号档数 | 散落 11/12/13/15/18/20 六种 | 收敛成 token：`--fs-xs 12 / --fs-sm 13 / --fs-md 15 / --fs-lg 18`（**不新增 11px**，低于 GDD §18.6 下限） |

### 7.2 配色与对比度（重点：审计而非重做）

现状 `--bg #0d0f12 / --panel #151a20 / --panel-2 #101317 / --line #232b34 / --fg #dbe4f0 /
--mut #8f9aa6`，已是**四层深灰 ＋ 无蓝相**，方向正确。

落点：
1. **补一个更暗的次要色 `--mut-2`**（用于时间戳这类「三等信息」），避免它们被迫用 `--mut`
   而挤占「二等信息」的层级；
2. **加一条 1px 的内描边高光**（`inset 0 1px 0 rgba(255,255,255,.04)`）给 `.panel` 类卡片 ——
   Material 的「白 overlay 提亮」做法，替代加边框撑高度；
3. **对比度审计脚本**（临时 `tools/_audit.mjs`）：把 `fg/mut/mut-2/up/down/gold/line` 在
   `bg/panel/panel-2` 上的 **WCAG 比值逐个算出来**并设阈值（正文 ≥ 4.5:1、大字与图形 ≥ 3:1）。
   跑完即删，**结论回写本节**（这是可验收的一条，不是口号）。

### 7.3 触摸与布局

| 项 | 现状 | 落点 |
|---|---|---|
| 底部 Tab 高度 | 44px（为 K 线让高度，**保留**） | 不动高度，但确认命中区 ≥44px；`#app` 已有 `env(safe-area-inset-bottom)` ✅ |
| 最小点击区 | 未逐项核过 | 逐项核：`.opt`（1/4·1/2·全部）、`.chip`、`.sym`、`.ic` 的实测高度是否 ≥44px，**不足的用透明 padding 补命中区、不撑高视觉** |
| 相邻可点间距 | 8px ✅（调研建议 ≥8pt） | 不动 |
| 拇指热区 | 主操作（动作键行）在底部 1/3 ✅ | 不动 |
| 窄屏 360px | **无任何 `@media`** | 新增一档 `@media (max-width:374px)`：只压字号（13→12）与 HUD 数字，不动间距 |
| 长按/点选 | 未设 `-webkit-tap-highlight-color` | 全局 `transparent`（现在 iOS/Android 会闪一块灰） |

### 7.4 动效與反馈（本项目**最大的缺口**）

全文件搜 `transition` **零命中**、`prefers-reduced-motion` **零命中**。落点：

1. **统一时长与缓动**：`--dur .18s` / `--ease cubic-bezier(.4,0,.2,1)`（调研：移动端 150–300ms）；
2. **按下态加强**：`.act:active` 现有 `brightness(.88)`，补 `transform: scale(.985)`（100ms）；
3. **切页与遮罩淡入**：`.page.on` 与 `#overlay` 的弹层加 120–180ms 淡入（**只加不透明度**，
   不位移 —— 高频操作下位移会晕）；
4. **K 线价格跳动 ≤150ms**：HUD 数字换值时只做一次短高亮（背景闪一下），不做滚动数字
   （挂机游戏那套 1s 滚动在本项目的高频刷新下会堆积卡顿）；
5. **`@media (prefers-reduced-motion: reduce)` 全关**（WCAG 2.3.3）；
6. **进度反馈**：币种解锁环已有动画 ✅，补一条「环完成时的一次性高亮」。

### 7.5 高密度与可读性

1. **涨跌不靠颜色单通道**：持仓条 / 资产页持仓行 / 日志串的盈亏数字前补 `▲` `▼`
   （约 8% 男性有色觉障碍，且暗底上红绿对比本就弱）；
