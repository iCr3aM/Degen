## 1. 关键结论：「早期把比特币全部买光」能不能做到

**数上可行，但现在代码买不光。**

## 2. 第一步 · 上帝面板 ＋ 订单冲击层（本次交付）

### 2.1 入口

顶栏那个 `<b>Degen</b>`（[render.js](file:///f:/Cr3aM/Desktop/Degen/src/ui/render.js#L43)）目前没有任何 `data-*`，而 [bind.js](file:///f:/Cr3aM/Desktop/Degen/src/ui/bind.js#L12-L20) 只派发带 `data-*` 的元素。做法与「重开本局」的二次确认同构：

- 给该 `<b>` 加 `data-god="tap"`；`ACTION_KEYS` 增补 `'god'`
- 连点计数状态机放 `main.js`（与 `onReset` 的 `resetArmed` 同一个理由：面板是静态 DOM，状态不能放渲染层）

### 2.2 状态新增

[state.js](file:///f:/Cr3aM/Desktop/Degen/src/core/state.js#L14-L97) 的 `createState()` 增加 **四个主状态字段** ＋ 一个 `god` 块：

```js
impactOn: true,     // 订单冲击总开关（基础玩法；设置面板可关）——在【主状态】而非 degen_settings
flow: {},           // 订单冲击池：sym -> { v, at }（v = 累计冲击量，at = 写入时的 s.i）
godRuined: false,   // 上帝模式下「已归零」的一次性提示标志

```

`god` 启用后为：

```js
god: {
  mult: 1,          // 冲击倍率（1 = 按现实平方根定律；面板可调 1~100）
  scale: {},        // 手动设价：sym -> 价格乘数（永久，直到「复位」）
```

**为什么 `impactOn` 必须在主状态、不能进 `degen_settings`（音效那种）**：它会改变权益、强平、滑点、资金费的计算结果，是**玩法逻辑**而非 UI 偏好；放进设置存档会出现「同一份存档在不同机器上跑出不同结果」。

`STATE_VERSION` 6 → 7，[save.js](file:///f:/Cr3aM/Desktop/Degen/src/core/save.js#L57-L77) 的 `migrate()` 补：`s.impactOn = true`、`s.flow = {}`、`s.godRuined = false`、`s.god = null`。老档升级后即默认开启冲击，与全局默认一致。

### 2.3 填入资金

面板里一个数字输入框 + 「填入」。语义是**直接设定当前交易所的余额**：


### 2.4 选日期 = **逐小时重放**

`s.i` 是唯一时间真相源（[state.js](file:///f:/Cr3aM/Desktop/Degen/src/core/state.js#L18)），所以跳日期**不能只改那个数字**——那等于把跳过的这段时间里的所有事件（Mt.Gox 2014-02-25 归零、币解锁、杠杆阶梯升级、借款到期、强平、资金费、转账到账）全部白送。

做法（复用现成的 `advanceOneHour`，零新增事件逻辑）：

```js
const target = clamp((Date.UTC(y, m - 1, d) - GAME.start) / HOUR_MS, s.i, GAME.candles - 1);
while (s.i < target && !s.over) advanceOneHour(s);
```

- 只允许**向前**跳；目标 ≤ 当前则拒绝并提示
- 面板用原生 `<input type="date">`，`min="2013-01-01"`、`max="2024-12-31"`（无需第三方控件）
- 重放是同步循环，`createClock` 的 `setInterval` 不可能插进来
- 重放中触发 `s.over`（到 2024-12-31 收盘）即停止
- 每根的成本是常数（**自动挂机已删除，不再有月度扫描这个 O(744) 的乘数**），10 万根在百毫秒级

### 2.5 爆仓不结束

[engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L321-L331) 的 `checkRuin` 顶部短路：


### 2.6 订单冲击层 —— 基础玩法（设置可关，默认开）

#### 收口点：只有一个

所有行情读取都走 [market.js](file:///f:/Cr3aM/Desktop/Degen/src/core/market.js#L109-L120) 的 `candleAt`（`closeAt` / `rangeOf` / UI 的 [view.js](file:///f:/Cr3aM/Desktop/Degen/src/ui/view.js#L95-L149) 日线聚合全部经由它）。只在这一处乘一个系数，**markPrice / 权益 / 强平价 / 资金费 / K 线图 / HUD 涨跌幅会全部自动跟上**，不需要逐个改。

market.js 侧新增（注入式，保持零依赖、不 import state）：

```js
let factorSource = null;
export function bindFactorSource(fn) { factorSource = fn; }   // main.js 注入：(sym, j) => f
const factorOf = (sym, j) => { const f = factorSource && factorSource(sym, j); return f > 0 ? f : 1; };
```

`candleAt` 里 `if (f !== 1) { o *= f; h *= f; l *= f; c *= f; }`——未启用时走原路径，**逐位相同**。

⚠️ **注意签名带 `j`**：系数是**逐根**的，不是全局常数（见下条）。这正是原方案那条「σ 不变」的安全前提失效的原因。

#### 系数公式

```
f(sym, j) = godScale[sym] × ( j < at ? 1 : 1 + v · decay(j − at) )

decay(e) = e <= 1 ? 1 : e ^ (−β)        β = 0.3，τ = 1 游戏小时
```

- `godScale[sym]`：上帝面板「砸盘」档位直接写（−10% / −30% / −50% / +100%），**全局永久乘数**，靠「复位」还原
- `v / at`：`s.flow[sym]`，订单造成冲击的**累计量**与写入时刻
- **`j < at` 时系数为 1**——一笔单只影响它**之后**的行情，不改历史。这是物理正确的口径（交易发生在 `at` 那一刻，价格路径从此处下台阶、再按幂律慢慢爬回）
- `β = 0.3` 取自 Bouchaud propagator 的实证量级；**衰减极慢**：1 小时后 100%、100 小时后 25%、1 万小时后 6%。砸下去基本回不来，但确实在慢慢回

⚠️ **σ 会变，缓存必须失效**（原方案此处判断有误，已纠正）：逐根系数 ⇒ 各根收盘价被不同比例缩放 ⇒ 相邻收益率改变 ⇒ σ_30日改变 ⇒ 滑点与资金费率连带改变。因此 [engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L127-L148) 的 `daySigmaCache` 与 `sigmaCache` **必须在每次写 `s.flow` 之后清空**：新增 `invalidateSigma()` 导出，在开/平仓写冲击处紧跟一行调用。否则会算出一个「价格在动、波动率不动」的不自洽滑点。

#### 谁写冲击、写多少

在 [engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L222-L233) 开仓处、平仓处各加一段（`s.impactOn` 为真时执行）：

```
Δ = SHOCK.share × impactOf(notional / liqOf(sym, day), dailySigma(sym, i)) × (s.god?.mult ?? 1)
买（开多 / 平空）⇒ v += Δ        卖（开空 / 平多）⇒ v -= Δ        同时 at = s.i
```

- `SHOCK.share = 0.35`：Almgren–Chriss 的**永久冲击占比**，实证 30–40%
- 复用现成的 `impactOf` / `liqOf` / `dailySigma`，不新增模型代码
- **不是重复收惩罚**（这点必须写进注释）：`impactOf` 是成交瞬间付出的**全部**代价；本层只把其中的 35% 沉淀为行情位移，剩下 65% 就是 AC 里的「暂时冲击」。同一笔代价没有被收两遍
- **OTC 成交不写 `flow`**：私下一口价的大宗交易不落公开盘口（与它不消耗供应量同一口径）
- 零售规模下绝大多数单的 `Δ` 是 0（滑点在 0.1 日流动性以下就判 0）⇒ 日常小单**几乎不影响行情**，只有大单/极端市况才推得动。这是设计意图，不是 bug
- 自动挂机已删除 ⇒ `mult` 只在上帝面板里调

#### 已知简化（首版采用，实机后复校）

- **单冲击池**：新单叠加进同一个池并重置 `at`，所以「分 10 笔买 1000 枚」的累积效果会**吃掉**前面的冲击，可能只剩最后一笔的量级。更精确要存「最近 N 笔列表」做 propagator 叠加——首版不做，标为待复校
- 系数按自然小时衰减，不区分币种特性

## 7. 第五层 · 美元 / USDT 货币体系

### 7.1 口径（**这是整层最关键的一条，定错了后面全歪**）

> **USDT 不是新的计价单位，它是一种「可持有、可兑换、汇率真实」的现金。**

- 数据包里的价格**全部是 USD 计价**（Bitstamp `BTCUSD`、Poloniex `ETH/USDT` 已在抓数时换算）——**计价单位不改**，一处都不改。
- 账户里 `usd` 与 `usdt` 是**两种现金**，USDT 要按 `usdtUsd(t)` 折算成 USD 才计入权益：

```
equity(s) = Σ_ex [ books[ex].usd + books[ex].usdt × usdtUsd(t) ]   ← 本层只改这一行
          + Σ_pos 仓位权益
          + (s.transfer ? s.transfer.amount : 0)                   ← 在途（本层也要分币种）
```

- 好处：**Mt.Gox 时代（只有美元）一行都不用特殊处理**；USDT 就是一个有 0.5%–15% 波动的现金选项 —— 这恰好就是「买 U 的溢价」这件事本身。
- ⚠️ **下单用哪种现金？** 建议：**优先扣 USDT、不足再用 USD**（真实所的顺序），**但合约保证金必须用 USDT**（GDD 是 USDT 本位永续）⇒ 这一条要在 §9 拍板。

### 7.3 数据产物：`public/data/usdt.bin`

- **长度与 K 线同轴**（105,192 根，2013-01-01 起），这样 `usdtUsd(i)` 的索引就与 `s.i` 完全一致，`market.js` 里加一个 `usdtAt(i)` 即可。
  前 2014-11 之前的值**写 0**（`usdtAt` 见到 0 返回 `null` ⇒ UI 显示「尚未发行」）。
- **编码**：汇率贴近 1，用**定点整数**比 Float32 省得多 —— `round((rate − 1) × 1e5)` 存 **Int32**：
  - 常态一根 = `0`（整段全 0 ⇒ gzip 几乎压到 0 字节）
  - 脱锚时 = `-4500`（= 0.955）
  - 相比 Float32 的 420 KB，**定点几乎全是 0，gzip 后预计 < 20 KB**（要实测）
- 数据入口写在 `tools/fetch-data.mjs`，源就是那个已经在硬盘上的 Kraken CSV（**$0、不联网**）。

### 7.4 「买U」动作

```
买U： 用 USD 换 USDT     花 usd 元，得 usd / (usdtUsd × (1 + 点差)) 个 U
卖U： 用 USDT 换 USD     花 usdt 个，得 usdt × usdtUsd × (1 − 点差) 美元
```

- **点差**：直接复用**当前交易所的 `fee`**（0.04%–0.20%）—— 不新造参数，与吃单费率同一套（LESS IS MORE）。
- ⚠️ **不再额外加「场外溢价」**：真实汇率 `usdtUsd(t) − 1` **本身就是那个溢价**（2018-10 的 −4.5%、2023-03 的 +0.5%）。再加一层就是收两遍。
  （人民币那条线你已排除，所以 `USDT/CNY` 那套 +5%/+8% 的数据**不引入**。）
- **门槛与频率**：**不设门槛、不设冷却**（买 U 是换钱，不是下单）；但**不产生订单冲击**（不写 `s.flow`，它不落盘口）。
- 状态：`books[ex].usd / .usdt` 两格互转，写一条日志。

### 7.5 资金曲线：`s.curve`

- **采样**：`advanceOneHour` 里当 `dayIndexOf(s.i)` 变化时，push 一个当天的**收盘权益（USD）**。
- **存储**：`s.curve`（Float 数组，长度 ≤ 4383）。⚠️ 用 `round(x × 100)` 的整数存（**分**）可以让 JSON 短一截且天然去噪。
- **体积**：4383 个整数 ≈ **35 KB** ⇒ `localStorage`（5 MB）完全放得下。**不入 `index.json`、不进数据包**（每局不同）。
- ⚠️ **上帝模式「跳到日期」会把 curve 一次性铺满 4383 个点** —— 这是正确行为（那段时间确实被模拟过了），但要在断言里覆盖。
- 绘图：`ui/curve.js`，只画折线 ＋ 首尾两个数；**不做坐标轴、不做缩放、不做 tooltip**（LESS IS MORE）。

### 7.6 `books` 结构改造（本层唯一的「外科手术」）

```js
// 现在
books: { mtgox: 3000 }
// 之后
books: { mtgox: { usd: 3000, usdt: 0 } }
```

`books[ex]` 的 **12 处**读写全部要走一对新函数，**不允许任何地方再直接写 `books[ex] = 数字`**：

```js
export const cashOf   = (s, ex = s.ex) => s.books[ex] ?? { usd: 0, usdt: 0 };   // 返回对象
export const cashUsdOf = (s, ex = s.ex) => { const b = cashOf(s, ex); return b.usd + b.usdt * usdtUsdAt(s.i); };
```

- ⚠️ **`cashOf` 的返回类型从数字变对象**，是一处**静默炸弹**：`equity` / `openTrade` 里 `cash - margin - fee` 这类算式会算成 `NaN` 而不报错。
  ⇒ 落地方针：**先把 `cashOf` 拆成 `cashOf`（对象）与 `cashUsd`（折算成 USD 的数字），再把 12 处逐一对上**，每一步跑一次断言。
- **在途转账**（`s.transfer.amount`）也要分币种：`{ usd, usdt }`，否则换所途中 USDT 会「变成美元」。
- **交易所归零**（Mt.Gox）：清空**该所两格**。
- **场外配资 `takeLoan`**：借来的是 **USD**（2013 年没有 U，这条天然自洽）。

## 8. 交易页改造

### 8.1 显式模式键 ＋ 资金费口径（**改判据，不改公式**）

```js
s.mode = 'spot' | 'fut'        // 默认 'spot'（= 2013 年 Mt.Gox 的天然形态），入存档
```

| 模式 | 允许 | 资金费 | 强平 | `pos.spot` |
|---|---|---|---|---|
| **现货** | 仅 1x 做多 | ❌ | ❌（只有币价归零才归零本金） | `true` |
| **合约** | 做多 / 做空，任意可用杠杆（**含 1x**） | ✅ **1x 做多也付** | ✅ | `false` |

- `openPosition` 多收一个 `spot` 参数，**开仓那一刻写死进 `pos.spot`**；`isSpot(pos)` 改成 `pos.spot === true`。
- ⚠️ **`isSpot` 的 5 处调用全部自动跟上**（engine 资金费 ×2 / engine OTC 守卫 / render 持仓条 / render 强平价 / main 警戒音），**这是选「改判据」而不是「到处加 if」的原因**。
- ⚠️ 模式与 `s.chan`（盘口/OTC）的关系：**OTC 只有现货**（GDD §15.3）⇒ 切到 OTC 时模式强制回 `'spot'` 且杠杆归 1（与现在 `onChan` 的行为同构）。
- ⚠️ **读数上要区分**：持仓条现在写 `${p.sym} 现货` 或 `${p.sym} 多 5x`，改后**合约 1x 做多**要显示成 `${p.sym} 多 1x`（而不是「现货」）—— 否则玩家看不出自己在付资金费。
- ⚠️ **GDD §9.1 那张「1x 做多 = 现货」的表要回写**（它写了「界面上不必多一行模式开关」—— 现在多了，理由变了：**玩家要能主动选择「付资金费换做空/强平能力」**）。

### 8.2 多笔加仓：`s.positions[sym]` → **数组（lot 列表）**

```js
positions: { BTC: [ {…lot1}, {…lot2} ] }   // 每笔 = 一个独立的逐仓仓位
```

- 开仓 = `s.positions[sym].push(pos)`；**每笔自带 `entry` / `margin` / `lev` / `spot` / `ex` / `otc`**，独立算强平价。
- 牵动 **12 处** `s.positions[sym]`：`posOf`（改成「取合计视图」或加 `lotsOf`）、`heldSyms`、`capturedOf`（**合计 `size`** 求和）、`equity`（逐笔求和）、`forceLiquidate` / `liquidateAll`（逐笔判定，只删爆掉那笔）、`collapseExchange`（删该所的全部笔）、`settleLoan`、资金费（逐笔收）、render 持仓条（合计展示）。
- 新增几个纯查询：`lotsOf(s, sym)` / `anyLot(s, sym)` / `sumOf(s, sym, f)`。
- ⚠️ **这个改动比 `books` 更危险**：`positions` 是「存档里最核心的资产」，迁移写错就是**老档全部资产消失**。迁移必须：`{...pos}` → `[pos]`，并用断言逐字段比对。

### 8.3 追加保证金

```js
export function addMargin(s, sym, amount)   // amount 来自 s.sizeFrac × 可用余额，或「全部」
```

- 作用对象：**该币保证金率最低的那一笔**（= 最危险的一笔）—— 这符合玩家意图，且**不需要额外的「选哪笔」UI**（LESS IS MORE）。
- 效果：`lot.margin += m`，`s.books` 扣 `m`。强平价与保证金率由 `positions.js` 的纯函数**自动重算**（它们只读 `pos.margin`，零改动）。
- ⚠️ 边界：`m` 不得使 `margin + 未实现盈亏 ≤ 0` 变得更糟 —— 实际上追加保证金**只会改善**强平价，无风险；但要拒绝 `m ≤ 0` 与 `m > 可用余额`。
- ⚠️ **现货模式下也可以追加**（等价于「补货」，会改变 `size`？**不改** `size` —— 追加保证金只加 `margin`，不买币；现货 1x 下 `size = margin × 1 / entry` 是**开仓时定的**，追加只改 margin ⇒ 这笔在现货模式下会变成「margin > notional」的畸形仓位）。⇒ **决定：现货模式下禁止追加保证金**（现货没有强平，追加保证金毫无意义）。**这一条写进 §9 待拍板。**

### 8.4 部分平仓（1/4 · 1/2 · 全部）

```js
export function closeTrade(s, frac = 1)
```

- **按 FIFO 部分平仓**（先开先平）：`frac` 是**总量的比例**，从最早那笔开始吃。
  - 例：两笔（$100 / $300），`frac = 0.5` ⇒ 平掉第一笔 $100 ＋ 第二笔的 $100（共 $200）。
- 手续费按**实际平掉的名义**收（`closePosition` 已是纯函数，改成按份额算即可）。
- ⚠️ **「金额」这一行的语义要在 UI 上讲清**：它**同时**作用于开仓与平仓 —— 现在是「用掉多少可用保证金」，平仓时是「平掉多少仓位」。**同一枚按钮、同一个 `s.sizeFrac`**（LESS IS MORE），但**标签要能读懂**：建议把行标签从「金额」改成动态的「开仓 / 平仓」（跟随已有持仓与否）。
- ⚠️ `frac = 1`（全部）必须与**现有行为逐位一致**（现有一行不动），否则老档的肌肉记忆会崩。

### 8.5 存档迁移 v7 → v8（一次把三件事做完）

```js
if (s.v === 7) {
  for (const k of Object.keys(s.books)) s.books[k] = { usd: s.books[k], usdt: 0 };  // 数字 → 双格
  for (const k of Object.keys(s.positions)) s.positions[k] = [s.positions[k]];      // 单仓 → 数组
  for (const lots of Object.values(s.positions)) for (const p of lots) p.spot = (p.side === 'long' && p.lev === 1);  // 显式标志：老档按旧规则判定
  if (s.transfer) s.transfer.amount = { usd: s.transfer.amount, usdt: 0 };
  s.curve = []; s.mode = 'spot'; s.tab = 'trade';
  s.v = 8;
}
```

> ⚠️ 老档的 `p.spot` 一律按**旧规则**（1x 做多）回填 —— 于是**升级后的老档语义完全不变**（那些仓位继续不付资金费），新玩法只对**新开的仓**生效。这是唯一不冤枉老档的做法。
