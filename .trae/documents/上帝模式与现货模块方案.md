## 2. 第一步 · 上帝面板 ＋ 订单冲击层（本次交付）

### 2.2 状态新增

[state.js](file:///f:/Cr3aM/Desktop/Degen/src/core/state.js#L14-L97) 的 `createState()` 增加 **四个主状态字段** ＋ 一个 `god` 块：

flow: {},           // 订单冲击池：sym -> { v, at }（v = 累计冲击量，at = 写入时的 s.i）

### 2.4 选日期 = **逐小时重放**

`s.i` 是唯一时间真相源（[state.js](file:///f:/Cr3aM/Desktop/Degen/src/core/state.js#L18)），所以跳日期**不能只改那个数字**——那等于把跳过的这段时间里的所有事件（Mt.Gox 2014-02-25 归零、币解锁、杠杆阶梯升级、借款到期、强平、资金费、转账到账）全部白送。

做法（复用现成的 `advanceOneHour`，零新增事件逻辑）：

```js
const target = clamp((Date.UTC(y, m - 1, d) - GAME.start) / HOUR_MS, s.i, GAME.candles - 1);
while (s.i < target && !s.over) advanceOneHour(s);
```

- 只允许**向前**跳；目标 ≤ 当前则拒绝并提示
- 面板用原生 `<input type="date">`，`min="2013-01-01"`、`max="2024-12-31"`（无需第三方控件）
- 重放是同步循环，`createClock` 的 `setInterval` 不可能插进来
- 重放中触发 `s.over`（到 2024-12-31 收盘）即停止
- 每根的成本是常数（**自动挂机已删除，不再有月度扫描这个 O(744) 的乘数**），10 万根在百毫秒级

### 2.6 订单冲击层 —— 基础玩法（设置可关，默认开）

#### 收口点：只有一个

所有行情读取都走 [market.js](file:///f:/Cr3aM/Desktop/Degen/src/core/market.js#L109-L120) 的 `candleAt`（`closeAt` / `rangeOf` / UI 的 [view.js](file:///f:/Cr3aM/Desktop/Degen/src/ui/view.js#L95-L149) 日线聚合全部经由它）。只在这一处乘一个系数，**markPrice / 权益 / 强平价 / 资金费 / K 线图 / HUD 涨跌幅会全部自动跟上**，不需要逐个改。

market.js 侧新增（注入式，保持零依赖、不 import state）：

```js
let factorSource = null;
export function bindFactorSource(fn) { factorSource = fn; }   // main.js 注入：(sym, j) => f
const factorOf = (sym, j) => { const f = factorSource && factorSource(sym, j); return f > 0 ? f : 1; };
```

`candleAt` 里 `if (f !== 1) { o *= f; h *= f; l *= f; c *= f; }`——未启用时走原路径，**逐位相同**。

⚠️ **注意签名带 `j`**：系数是**逐根**的，不是全局常数（见下条）。这正是原方案那条「σ 不变」的安全前提失效的原因。

#### 系数公式

```
f(sym, j) = godScale[sym] × ( j < at ? 1 : 1 + v · decay(j − at) )

decay(e) = e <= 1 ? 1 : e ^ (−β)        β = 0.3，τ = 1 游戏小时
```

- `godScale[sym]`：上帝面板「砸盘」档位直接写（−10% / −30% / −50% / +100%），**全局永久乘数**，靠「复位」还原
- `v / at`：`s.flow[sym]`，订单造成冲击的**累计量**与写入时刻
- **`j < at` 时系数为 1**——一笔单只影响它**之后**的行情，不改历史。这是物理正确的口径（交易发生在 `at` 那一刻，价格路径从此处下台阶、再按幂律慢慢爬回）
- `β = 0.3` 取自 Bouchaud propagator 的实证量级；**衰减极慢**：1 小时后 100%、100 小时后 25%、1 万小时后 6%。砸下去基本回不来，但确实在慢慢回

⚠️ **σ 会变，缓存必须失效**（原方案此处判断有误，已纠正）：逐根系数 ⇒ 各根收盘价被不同比例缩放 ⇒ 相邻收益率改变 ⇒ σ_30日改变 ⇒ 滑点与资金费率连带改变。因此 [engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L127-L148) 的 `daySigmaCache` 与 `sigmaCache` **必须在每次写 `s.flow` 之后清空**：新增 `invalidateSigma()` 导出，在开/平仓写冲击处紧跟一行调用。否则会算出一个「价格在动、波动率不动」的不自洽滑点。

#### 谁写冲击、写多少

在 [engine.js](file:///f:/Cr3aM/Desktop/Degen/src/core/engine.js#L222-L233) 开仓处、平仓处各加一段（`s.impactOn` 为真时执行）：

```
Δ = SHOCK.share × impactOf(notional / liqOf(sym, day), dailySigma(sym, i)) × (s.god?.mult ?? 1)
买（开多 / 平空）⇒ v += Δ        卖（开空 / 平多）⇒ v -= Δ        同时 at = s.i
```

- `SHOCK.share = 0.35`：Almgren–Chriss 的**永久冲击占比**，实证 30–40%
- 复用现成的 `impactOf` / `liqOf` / `dailySigma`，不新增模型代码
- **不是重复收惩罚**（这点必须写进注释）：`impactOf` 是成交瞬间付出的**全部**代价；本层只把其中的 35% 沉淀为行情位移，剩下 65% 就是 AC 里的「暂时冲击」。同一笔代价没有被收两遍
- **OTC 成交不写 `flow`**：私下一口价的大宗交易不落公开盘口（与它不消耗供应量同一口径）
- 零售规模下绝大多数单的 `Δ` 是 0（滑点在 0.1 日流动性以下就判 0）⇒ 日常小单**几乎不影响行情**，只有大单/极端市况才推得动。这是设计意图，不是 bug
- 自动挂机已删除 ⇒ `mult` 只在上帝面板里调

#### 已知简化（首版采用，实机后复校）

- **单冲击池**：新单叠加进同一个池并重置 `at`，所以「分 10 笔买 1000 枚」的累积效果会**吃掉**前面的冲击，可能只剩最后一笔的量级。更精确要存「最近 N 笔列表」做 propagator 叠加——首版不做，标为待复校
- 系数按自然小时衰减，不区分币种特性

## 3. 第二步 · 现货屯币模块（待审核后再动）

要点先摆出来，**这一层不写代码**：

- 新增 `s.holdings = { BTC: 0, ... }`（现货余额，与 `positions` 平行）
- 新增 `s.consumed = { BTC: 0, ... }`（**累计买走枚数**）——`capturedOf` 的瞬时口径换成它，才谈得上「买光」
- 关键分歧：**卖出是否退还累计消耗**？
  - 退还 = 模拟「流通盘被临时锁走」
  - 不退还 = 模拟「币真的被你囤走了」（更像你要的「买光」）
