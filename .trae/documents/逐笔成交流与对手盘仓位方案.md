## 1. 30 秒档「规律山峰」—— 真凶与修法

### 1.1 现象与复现路径

把 K 线捏合放大到跨度 < 12 小时时会自动切到 `1t` 档（`view.js` L270–275），一屏最多 `FINE_MAX = 12 × 120 = 1440` 根 tick（`view.js` L31）。390px 屏下每桶 ≈ 7 根 tick ⇒ 一小时约 17 根柱子。

于是 vol 柱呈现：**每个整点一根尖顶、24 根/天、天天一模一样**。用户描述为「一座一座有规律的山峰」。

### 1.2 真凶 A：细档的量口径与真实小时份额**脱钩**（决定性）

`view.js` 的 `fineWindow()`（L187–236）里：

```js
// L212：每次跨小时只取一次日流动性
dayLiq = liqOf(sym, dayIndexOf(hh)) || 0;
// L226：桶内 tick 的量
vol += w[j] * dayLiq;
```

而 `Σ_j w[j] ≡ 1`（`simulate.js` L167 归一化）⇒ **每一个小时的总量都恒等于 `dayLiq`**。

对照粗档（L168–169）：

```js
const share = volumeAt(sym, k);
vols.push(share > 0 ? share * (liqOf(sym, dayIndexOf(k)) || 0) : 0);
```

粗档用的是**该小时的真实份额** `volumeAt(sym, k)`（数据包里每根 K 自带的那 1 个字节，`market.js` L163–168，`/255`）。

> ⚠️ **两档口径不一致，且 `fineWindow` 的注释自己写的是对的**（L180：「量 ＝ 桶内 tick 权重之和 × **该小时绝对成交额**」）——代码却乘了日流动性。
> **这是注释与代码不符，属 bug 级**：它让 `1t` 档里**每个小时一样高**，真实行情的量差被整段丢掉。

而「真实小时份额」恰恰是**唯一能提供自然起伏**的东西——它逐小时、逐日都不同（白天夜里、暴涨暴跌倒量）。

### 1.3 真凶 B：U 型曲线被用错了**尺度**

`simulate.js` 的 `weightsOf()`（L151–171）：

```js
const e = 2 * ((i + 0.5) / N) - 1;                        // −1 … 1（小时内位置）
const u = 0.5 + 1.5 * e * e;                              // 两端 2、正中 0.5 ⇒ 端/中 = 4×
const z = rand(seed, symH, hour, i, CH_VOLUME) * 2 - 1;
const v = u * (1 + VOL_ETA * z);                          // VOL_ETA = 0.35
```

文件头的口径引用是 **Jain & Joh 1988 / Admati & Pfleiderer 1988** —— 那两篇讲的是**日内**（开盘、收盘活跃，午间清淡）的 U 型，**不是「每个小时内部」的 U 型**。

当前实现的后果：

- 每个整点：上一小时最后一根 tick 的 `e ≈ +1`（u ≈ 2）、下一小时第一根 tick 的 `e ≈ −1`（u ≈ 2）⇒ **两枚高柱正好撞在小时边界上**；
- 而桶在小时边界被**强制切**（L205，为保锚点，不能动）⇒ 尖顶精确落在桶沿，视觉上格外整齐；
- 噪声只有 ±35%，压不住 4× 的系统性落差。

> 结论：**A 决定「山峰一样高」，B 决定「每个整点都长角」。** 两个都修，或至少修 A。

### 1.4 修法

#### A（必做，1 行，`src/ui/view.js`）

把桶内的 tick 量乘回**该小时的真实份额**，与粗档同源：

```js
// L207–213 的 if 块内，取小时时同时取真实份额
if (hh !== lastHour) {
  lastHour = hh;
  const cc = candleAt(sym, hh);
  path = cc ? pathOf(seed, sym, hh, cc) : null;
  w = cc ? weightsOf(seed, sym, hh) : null;
  dayLiq = liqOf(sym, dayIndexOf(hh)) || 0;
  hourUsd = (cc ? volumeAt(sym, hh) : 0) * dayLiq;   // ← 新增：该小时绝对成交额
}
// L226
vol += w[j] * hourUsd;                                // ← 原 w[j] * dayLiq
```

- 缺根 / 未上线的小时 `volumeAt` 回 0 ⇒ `hourUsd = 0` ⇒ 该小时无柱，与粗档「无成交」口径一致；
- `Σ_j w[j] = 1` ⇒ 桶量之和 = 该小时真实成交额，**与 `1h` 档可逐小时对齐**；
- 顺带修正了一处语义错误：现在 `1t` 一屏 12 小时的总量不再恒等于 `12 × dayLiq`。

#### B（建议做，≈5 行，`src/core/simulate.js`）

把 U 型的相位从「小时内」搬到「**日内**」，让曲线**跨小时连续**：

```js
// weightsOf 内，替换 L160–161：
const hd = ((hour % 24) + 24) % 24;                       // 该小时在一天里的第几小时
...
for (let i = 0; i < N; i++) {
  const x = (hd + (i + 0.5) / N) / 24;                    // 0 … 1 —— 日内位置，跨小时连续
  const e = 2 * x - 1;                                    // −1 … 1
  const u = 0.5 + 1.5 * e * e;                            // 仍然两端 2、正中 0.5
  ...
}
```

效果与代价：

- 相邻小时的边界处 `x` 只差 `1/11520` ⇒ **不再有整点尖角**；一天只有「零点高、正午低」一条平滑 U；
- 小时**内部**几乎平坦 —— 这正确：真正的 U 是日内尺度，不是小时尺度；
- `s.i = 0` 恰为 `2013-01-01T00:00Z`（`config.js` L19）⇒ `hour % 24` 就是 UTC 时钟，口径干净；
  ⚠️ 若将来把 `GAME.start` 挪到非整点，只是相位平移，连续性与可复现性不受影响；
- 缓存 key（`sym|hour|seed`）不变，LRU 行为不变。

> 备选 B′（更小）：保留小时节奏，只把 `u` 的幅度从 `0.5 + 1.5e²` 压到 `0.85 + 0.45e²`（端/中 ≈ 1.5×）。不改尺度、只改幅度，能去掉一半假感但整点仍是尖角。**不推荐**，因为它没有修正「尺度用错」这个根因。

### 1.5 明确不动的部分（红线）

- `pathOf()` 的布朗桥 ＋ 两侧归一：**一字不改**（S1 红线 1：`max ≡ H`、`min ≡ L`，爆仓/致命针全依赖它）；
- 数据包 **17 字节/根**不动、`STATE_VERSION` 不动（tick 本就不进存档、不进数据包）；
- `VOL_ETA`、`CH_VOLUME` 通道、LRU 上限不动；
- 桶不跨小时（`view.js` L205）不动 —— 它是 §1.3 里「尖顶对齐」的放大器，但更是锚点不破的前提。

## 2. 逐笔成交流能不能模拟？

### 2.1 我们手里已经有的

| 数据 | 来源 | 粒度 |
|---|---|---|
| 真实小时 OHLC | 数据包（Bitstamp 等真小时线） | 1 小时，**硬锚点** |
| 真实小时成交额份额 | 数据包第 5 字节 `/255`，`market.volumeAt()` | 1 小时 |
| 日内成交额的绝对量级 | `liqOf(sym, day)` 日流动性 | 1 天 |
| 小时内的**价格路径** | `simulate.pathOf()`，120 个价点 | 30 秒 |
| 小时内的**量权重** | `simulate.weightsOf()`，120 个权重 | 30 秒 |

⇒ **「每 30 秒的价 × 每 30 秒的量」我们已经有了**，这也是 `1t` 档的画法来源。

### 2.2 缺的三样（数据包里没有，现实里也拿不到）

「逐笔成交流 / tape」在交易所网站上长这样：`时间 · 价格 · 数量 · 方向(主动买/主动卖)`。缺的是：

1. **笔数**：这一小时内成交了多少笔？（现货 BTC 一小时内可能是几十万笔）
2. **每笔数量分布**：真实是重尾（幂律 / Zipf），少数巨鲸单 + 大量碎单；
3. **主动方向**：这一笔是吃买单还是吃卖单（只有真实 tick 数据或 order book 才有）。

这三样**任何权威免费源都给不了 12 年 × 5 币**的完整历史；自己编一个分布 = 用一个和真实无关的假设去表演「真实感」。

### 2.3 结论与建议

**技术上能合成，但不建议做**，理由三条：

1. **不可校准**：编出来的笔数/单量分布没有任何真实数据可以对照，改一个参数就换一种「假法」，属于自欺；
2. **无消费方**：当前 `src/` 里**没有任何 UI 读 tick 级成交**（`weightsOf` 的唯一消费方是 `view.js` 的 `1t` 档量柱）。做 tape 等于既造数据又造 UI；
3. **与 LESS IS MORE 冲突**：手机竖屏的空间预算是硬约束（`1t` 档、日志浮层、持仓条都刚抢过位置），再塞一个成交流面板不划算。

> 若确定要做，**唯一诚实的形态**是「**派生视图**」而非「**新数据**」：
> 复用已有的 120 点 `pathOf` + 120 个 `weightsOf`，画一条 `价 · 量` 的最近 N 条流水，方向由**该 tick 的价格涨跌**派生（涨=主动买、跌=主动卖）。
> 但请注意：这个「方向」与我们自己合成的价格路径**同源**，是循环论证 —— 它不会提供任何价格路径之外的信息。

**建议**：先做 §1；`1t` 档量柱修好之后，如果仍想强化「有人在交易」的感觉，优先考虑**给 tick 量柱按该 tick 价格涨跌上色**（成本≈0、无新数据），而不是造一条 tape。

## 3. 对手盘仓位能不能模拟？

### 3.1 为什么不行（三条，按重要性排序）

1. **物理上没输入**：数据包每根只有 `O/H/L/C × 4 字节 + 量份额 1 字节`。没有 order book、没有 open interest、没有 funding、没有多空账户数。**「谁在对立面、持多少仓」这件事，在输入里一个比特都没有。**

2. **要做就得是 ABM，而 ABM 必须动价格**：要让「对手盘仓位」有意义（即：他们的行为反过来影响你），就得让一堆 agent 的净持仓**驱动价格**。但我们的小时 OHLC 是 **真实硬锚**——
   - 若 agent 不影响价格 ⇒ 他们只是布景，**是假的**；
   - 若 agent 影响价格 ⇒ 直接推翻已关闭的裁决。

   > ⚠️ **该议题已于 2026-09-29 复核关闭**（项目硬约束）：
   > 「锚点只合成『真实数据里拿不到的量』（链上拥堵 / 到账时间）；**价格与波动率一律用真实小时线，绝不注入人工涨跌幅**。」
   > 在价格上叠加合成流 = **对同一事件双重计价**，且会与**订单冲击**的 `factorSource`（`market.js` L141–144）抢同一根 K 线。

3. **现有「订单冲击」已经是约化的对手盘**：`impact.js` / `god.js` 的 `factorSource` 让**玩家自己的成交量**按 `A · σ_30日 · sqrt(min(q, 0.25))` 反向推动价格 —— 这就是「对手盘」在**可校准**形式下能给出的全部：流动性深度。再往前一步就没有真实数据兜底了。

### 3.2 已有 vs 想要的

| 维度 | 现在有 | 「对手盘仓位」想要 |
|---|---|---|
| 玩家单量对价格的冲击 | ✅ `impact.js`（真实流动性刻度） | 同 |
| 深度/滑点 | ✅ `liqOf` 日流动性 ＋ 平方根定律 | 同 |
| 「对面有多少人在做反向」 | ❌ 无、且无数据源 | ❌ 目标 |
| 对手盘爆仓 → 连锁 | ❌ 无、且需 ABM | ❌ 目标 |

### 3.3 一处需要更正的区分：**只读回测 ≠ 会回写价格的 ABM**

用户追问「不能用真实小时线**回测**模拟对手盘仓位吗？」—— 这个问法指向的东西，和 §3.1 第 2 条否掉的东西**不是同一件**：

| | 只读回测（用户问的） | 会回写价格的 ABM（§3.1 否掉的） |
|---|---|---|
| 价格怎么来 | **读**真实小时线 | 由 agent 净持仓**算**出来 |
| 合成体的盈亏 | 由真实价格路径**结算** | 由自己造的价格结算 |
| 是否违反硬锚 | ❌ **不违反** | ✅ 违反（＝对同一事件双重计价） |
| 能否实现 | **能** —— 而且不需要任何新数据包 | 不能 |

⇒ **更正如上**：只读回测在技术上**可行且不违反约束**。它仍然被建议不做，但理由**只剩两条**（不再是「不可能」）：

1. **不可校准**：这群人的**数量 / 规模 / 入场点 / 杠杆**在真实数据里没有对照物（12 年 × 5 币没有 OI、多空比、账户数历史）⇒ 仓位是编的；
2. **没有出口**：它不产生任何玩法信号 —— 除非它反过来影响流动性或价格，而影响价格恰好就是上表右列那条被否掉的路。

也就是说：**能做，但只能当装饰。** 要不要这个装饰，由用户定（见 §4 的 P-E）。

### 3.4 建议

**不做。** 若将来确要做「对手盘氛围」，唯一不违反约束的形态是：

- **纯展示、且明确标注为机制化合成**（照 `GDD §15.3` OTC 溢价那种写法：机制化处理、非史实还原）；
- 且**绝不回写价格**。

但即使这样，它也只是一个没有玩法钩子的装饰数字 —— 建议仍然不做。
