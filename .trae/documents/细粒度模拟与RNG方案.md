## §1 一句话结论

**可行**，而且是金融仿真里的**成熟范式**（「低采样率插值出高采样率、同时保留动力学」，Schaug & Chandra 2019）；但**不是免费** ——
它推翻的是项目最核心的一条硬约束（「不用合成价格」），代价必须一次说清。据此给出**五条定论**：

| # | 问题 | 结论 |
|---|---|---|
| **①** | 方法论可行吗？ | ✅ **可行**。每小时真实 OHLC 作**硬锚点**（O/C 精确命中，H/L 精确钉住），小时内部用**种子化布朗桥 ＋ 钉极值**生成细路径 |
| **②** | 选哪个粒度？ | ✅ **30 秒为主力粒度**（1 分钟可选、1 秒不建议）；**渲染与模拟解耦**：主图仍画 1 小时聚合，放大才展开细 K |
| **③** | RNG 种子系统？ | ✅ **必须无状态哈希式**（`splitmix64` → `mulberry32`），种子 ＝ `f(全局种子, 币种, 小时序号, 刻度序号)`，天生可复现 ＋ 可断点续算 ＋ 可并行 |
| **④** | 之前被否的能接入吗？ | ✅ **大部分能**：30 分钟粒度 ✓、逐档盘口/分批成交（C8-B）✓、用针爆仓 ✓、资金费细周期 ✓、交易所规则史实化（B18–B25）✓、B26 永续区分 ✓ |
| **⑤** | 肉鸽化怎么落？ | ✅ **真实小时线 ＝ 地形底图（固定）＋ 种子化事件/插针/资金费 ＝ 词条（每局随机）**，与既有 20 条**历史锚点**天然咬合 |

**⚠️ 最大的风险（务必先想清楚）**：**「锚点对了、路径是假的」** —— 一旦玩家发现小时内部走势可被预测/利用，会失去对行情的信任。
**对策**：① 把口径**写进代码注释**（**只写注释** —— 本项目**本身就是模拟器**，UI 与文档都**不做**「这是模拟」的声明）；② 提供**路径校验器**（玩家可验证 O/C 命中、H/L 命中）；③ 把「可预测性」**做成玩法**（资金费/插针/爆仓条件对玩家公开），而不是藏起来的假象。

## §3 新架构：三层时间轴

### 3.1 三个刻度，各司其职

```
 真实小时线（硬锚点，来自数据包，永不改）
   │  每根 = 1 个「锚点小时」，OHLC 四值必须逐位命中
   ▼
 细刻度 tick（模拟生成，带种子，懒生成不落盘）
   │  每小时内 N 根；主干 = 30 秒（N=120），可选 1 分钟（N=60）
   ▼
 聚合视图（渲染/玩法共用）
     主图默认仍画 1 小时聚合 → 放大后展开为 tick 蜡烛 → 再缩回聚合
```

### 3.2 粒度选型（含算出来的量）

12 年 ＝ 365 × 24 × 12 ＝ **105,120 小时**（项目实际 `GAME.candles = 105192`）。

| 候选粒度 | 每小时内 tick 数 | 全 12 年总量 | 评价 |
|---|---|---|---|
| **1 秒** | 3,600 | **378,432,000（3.78 亿）** | ❌ 生成 + 渲染都不现实，且无必要 |
| **30 秒** | 120 | **12,614,400（1,261 万）** | ✅ **主力**（与真实数据同源：1 分钟是交易所原生档位，30 秒是其一半） |
| **1 分钟** | 60 | **6,307,200（631 万）** | ✅ **可选**（更省，但「针」的密度略低） |
| 5 分钟 | 12 | 1,261,440 | 🟡 作为「放大档」的中间 LOD |
| 30 分钟 | 2 | 210,240 | 🟡 中间 LOD |

**关键取舍**：**模拟粒度 ≠ 渲染粒度**。
- **模拟**按 30 秒（或 1 分钟）算，只算**当前视野 ＋ 预取边界**（懒生成，rolling window）；
- **渲染**远缩放时画 **1 小时聚合**（与今天完全一样，玩家看不出差别），近缩放才展开细 K；
- **绝不预生成全量**（6.3M~12.6M 根），靠 `(seed, hour, k)` 无状态寻址「跳到任意位置即算」。

### 3.3 1x 速度的手感（必须重定）

今天：**1x ⇒ 1 游戏小时 = 1 真实秒**（[config.js](file:///f:/Cr3aM/Desktop/Degen/src/core/config.js) `SPEEDS`），12 年 ≈ 29 小时真实。
若改「1 游戏**分钟** = 1 真实秒」，12 年 → 631 万秒 ≈ **73 天真实** ⇒ 显然不可接受。

**⇒ 速度必须按「锚点小时」而不是「tick」定**：`1x` 仍然是「1 游戏小时 = 1 真实秒」，**tick 只是小时内部的采样放大**。
玩家拖动/缩放看细节时**暂停时钟**（不进 tick），这样「时间推进」与「观察粒度」彻底解耦。
`SPEEDS = [1,5,10,50]` **保持不动**。

## §4 RNG 种子系统（整套的地基，先做这个）

### 4.1 为什么必须「无状态哈希式」

| 方案 | 可复现 | 断点续算 | 多币并行 | 评价 |
|---|---|---|---|---|
| 流式单一 PRNG（一直 `next()`） | ✓ | ❌ 要重放 | ❌ 顺序耦合 | ❌ 不可用 |
| **无状态 counter-based**：`seed = hash(全局种子, 币种, 小时, 刻度)` | ✓ | ✓ 跳到哪算哪 | ✓ 互不干扰 | ✅ **唯一可行** |

依据：`rand_philox` 的契约 ——「每个词都是 `(key, counter)` 的纯函数，重跑任意抽签结果一致，与线程数无关」；
KineticSim（arXiv:2606.21784）用 **stateless counter-based SplitMix64** 给 `(agent/market/step/channel)` 定坐标；`mulberry32` 在 JS 基准里最快（≈73 Mops/s）。

### 4.2 种子设计（写死口径）

```
全局种子 globalSeed : uint32（开局随机一次 / 存档可指定 = 肉鸽「种子局」）
接着 hour : 自 2013-01-01 起的绝对小时序号（= 今天的 s.i 语义，保持不变）
      sym : 币符号（哈希成 uint32）
      tick : 该小时内第几根细 K（0 ≤ tick < N）
      channel : 用途通道（'path' / 'volume' / 'extreme' / 'event' …）

seed(sym, hour, tick, channel)
   = splitmix64( (globalSeed ★) ⊕ hash(sym) ⊕ hour × K1 ⊕ tick × K2 ⊕ hash(channel) )
   → 取低 32 位 → mulberry32 → 均匀数
```

**要点**
- **`hour` 沿用今天的 `s.i`** （绝不换刻度）⇒ `anchors` / `arrivalCandles` / `FUNDING` / `LOAN` 的**天数换算全部零改动**；
- **`channel` 分离** ⇒ 行情路径 / 成交量 / 极值位置 / 事件 四套随机数**互不污染**，将来加模块不会打乱已有序列；
- **`globalSeed` 入存档** ⇒ 同一存档同一时刻同一币种，**永远生成同一条 tick 流**（可复现、可回放、可分享种子局）；
- **无状态** ⇒ 断点续算、跳日期（上帝模式）、快速拖动，都不需要重放。

### 4.3 极简实现（≤ 20 行，纯原生 JS，零依赖）

```js
const M64 = 0x9e3779b97f4a7c15n;
function splitmix64(x) {                       // x: BigInt
  x = (x + M64) & 0xffffffffffffffffn;
  x = ((x ^ (x >> 30n)) * 0xbf58476d1ce4e5b9n) & 0xffffffffffffffffn;
  x = ((x ^ (x >> 27n)) * 0x94d049bb133111ebn) & 0xffffffffffffffffn;
  return (x ^ (x >> 31n)) & 0xffffffffffffffffn;
}
function mulberry32(a) {                       // 单次取样
  a |= 0; a = (a + 0x6D2B79F5) | 0;
  let t = Math.imul(a ^ (a >>> 15), 1 | a);
  t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
  return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
}
/** 无状态取一个 [0,1) —— 任意 (种子, 币, 小时, 刻度, 通道) 直接算，不依赖调用顺序 */
export function rand(seed, symHash, hour, tick, chanHash) {
  const h = splitmix64(
    (BigInt(seed) * 0x100000001b3n) ^
    (BigInt(symHash) << 32n) ^
    (BigInt(hour) * 0x9E3779B1n) ^
    (BigInt(tick) * 0xC2B2AE3Dn) ^
    BigInt(chanHash)
  );
  return mulberry32(Number(h & 0xffffffffn));
}
```
> ⚠️ 若要「同一小时取**多个**随机数」（如路径需要 N−1 个增量），把 `tick` 就当作序号：
> `rand(seed, sym, hour, k, 'path')`，k = 1…N−1 —— 每个 tick 一次调用，**天然无状态、可并行**。

## §5 小时内部怎么生成（数学口径）

### 5.1 价格路径：**布朗桥（两端精确命中）**

把一根真实小时 K 的 4 个值 `(O, H, L, C)` 当作约束。**第一步**只钉两端（O 与 C）：

```
x[0] = O,  x[N] = C
for k in 1..N-1:
    u = k / N
    mean = O + (C − O) · u             # 线性插值（漂移）
    v    = σ_h² · u · (1 − u)          # 布朗桥条件方差：两端为 0，中点最大
    x[k] = mean + sqrt(v) · gauss(rand(seed, sym, hour, k, 'path'))
```
- `σ_h` ＝ **该小时的真实波动量**（用 `H − L` 或 `|C − O|` 反推，保证细路径的幅度与真实小时一致）；
- `gauss` ＝ 由均匀数转正态（Box–Muller / 逆 CDF），输入用 `rand(...)`；
- 结果：**O 与 C 精确命中**，中间走势随机但幅度守恒。

**为什么是布朗桥**：业界标准做法（NAG g05 把布朗桥定义为「两端固定的 Wiener 过程」）；Schaug & Chandra (arXiv:1911.10972) 明确指出布朗桥/OU 桥正是「低采样率 → 高采样率插值且保留动力学」的行业手段，并被银行用于 VaR 数据质量补救。

### 5.2 极值钉住：**先桥、后钉**（保证 H/L 精确）

布朗桥不保证撞到真实的 H / L。**第二步**做「钉极值」：

```
iH = argmax_k x[k]            # 取极值位置（或用 U 型权重采样，让针更靠中后段）
if x[iH] > O:                 # 只放大，不缩小（避免破坏 C）
    s = (H − O) / (x[iH] − O)
    for k in 0..iH: x[k] = O + (x[k] − O) · s      # 使 x[iH] == H
# 对 L 同理（向 O 的另一侧），最后再整体校验 x[N] == C
```
- 更严谨的版本是「**条件极值的桥**」（meander ＋ 区间约束桥，arXiv:2609.26739：保留精确极值**及其位置**）；
- **插针（针）比整根影线更真实**：真实市场的插针 = 单 tick 极端影线 ＋ 成交额放大一个量级（DolphinDB 对 2025-10-10 的复盘），**这正是爆仓连环的产物** —— 也正是这个游戏（100x 玩法）最需要的。

### 5.3 成交量：**U 型曲线 ＋ 噪声，总量守恒**

```
w[k] = Ushape(k / N) · (1 + η · z[k])      # U 型日内曲线 × 种子噪声
vol[k] = hourQuote · w[k] / Σw             # 归一 ⇒ 小时总成交额守恒（不新增数据）
```
- 股票 U 型量曲线有理论与实证基础（Jain & Joh 1988；Admati & Pfleiderer 1988）；
- **加密市场也是 U 型但锚点不同**：Binance 在 **00:00 与 16:00 UTC 有尖峰**（Alexander/Heck/Kaeck, arXiv:2107.00298），**小时内还有与资金费时间相关的周期性**（Hansen/Kim/Kimbrough, arXiv:2109.12142）——**这一点与游戏的 8 小时资金费天然咬合**。

### 5.4 波动率一致性（一个陷阱）

**√时间缩放只在 H = 0.5 时成立**。用布朗桥（H = 0.5）⇒ 放大回看自然自洽；
**不要**直接拿 fBm 当价格（H ≠ 0.5 会破坏 √t 直觉、且带来视觉抖动噪声）。
若要「波动聚集」，把 `σ(t)` 单独用低 H（0.1~0.3）的 fBm/OU 调制，再按 `σ(t)·√Δt` 生成增量（rough vol 实证 H ≈ 0.1）。

## §7 粒度建议：**30 秒为主力**

| 维度 | 1 秒 | **30 秒（推荐）** | 1 分钟 | 30 分钟 |
|---|---|---|---|---|
| 全 12 年总量 | 3.78 亿 ❌ | **1,261 万 ✓** | 631 万 ✓ | 21 万 ✓ |

| 生成/渲染压力 | 不可行 | **可控（懒生成 ＋ LOD）** | 低 | 极低 |

**渲染与模拟解耦**：主图默认仍是今天的样子（1 小时聚合），**只有玩家主动放大**才展开细 K ——「more」加在**深度**上，不加在**默认复杂度**上。

## §11 风险与红线

| 风险 | 说明 | 对策 |
|---|---|---|
| **可信度** | 「锚点对了、路径是假的」——玩家发现小时内部可预测 ⇒ 失去信任 | **口径只写进代码注释**（本项目**本身就是模拟器**，UI / 文档**不做**声明）＋ **路径校验器** ＋ 把可预测性做成玩法 |
| **可速通** | 肉鸽＝可复现 ⇒ 种子局会被研究/速通 | **这是特性不是 bug**（每日挑战正是靠它）；但**锚点顺序不可随机**（否则历史叙事崩） |
| **性能** | 3.78 亿 tick 若误预生成 ⇒ 崩 | **只做懒生成**；1 秒档默认关；渲染必走 LOD |
| **复杂度反弹** | 「more」若无节制 ⇒ 破坏 LESS IS MORE | **每加一个模块都必须能用种子复现 ＋ 必须能过 §10 验证口径**；默认界面**保持今天的样子**，深度藏在放大里 |
| **数学自洽** | fBm 直接当价格会破坏 √t | 价格用 H=0.5 桥；波动率调制才用低 H |
| **合规/叙事** | 「假行情」的观感 | 依 Schaug & Chandra：**「约束已知锚点、合成未知细路径」在业内是被接受的**（银行用于 VaR / 压力测试），**前提是口径可查** —— 本项目把口径写在**代码注释**里，**UI 不做任何声明**（因为**它本来就是模拟器**） |
